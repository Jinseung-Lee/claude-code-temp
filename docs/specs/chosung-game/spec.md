# 초성게임 (멀티모드 + 싱글모드)

## User-visible outcomes

지인들이 URL 공유만으로 방에 모여 멀티모드로 초성게임 10라운드를 겨루고 순위를 확인할 수 있다. 혼자서도 싱글모드로 제한시간 내 타임어택 기록에 도전할 수 있다.

## Approved scope

- 게임 접속: 첫 진입 시 닉네임(아이디)을 한 번 만들고, 그 뒤에 싱글모드·멀티모드를 고른다. 만든 닉네임은 기억되어 이후 방 참여·싱글모드에 그대로 쓰인다.
- 멀티모드: 방 생성/참여(URL + 저장된 닉네임), 대기실 참가자 목록과 채팅, 방장의 카테고리·난이도 설정, 라운드 진행(초성 제시 → 아이템 사용 → 정답 판정), 라운드 중 별도의 아이템 획득용 미니 문제, 실시간 순위 사이드바, 10라운드 진행 후 순위 발표
- 게임 이탈: 싱글모드·멀티모드 진행 중 언제든 게임 종료 버튼으로 홈으로 돌아간다. 멀티방에서 나가면 그 방의 참가자 목록에서 제거되고, 남은 인원이 1명이면 그 1명의 승리로 게임이 즉시 끝난다.
- 방 목록: 각 방의 참가자 이름 목록과 현재 순위를 함께 보여준다.
- 싱글모드: 여러 초성 문제가 위에서 아래로 순차적으로 떨어지는 화면에서 제한시간 내 최대한 많이 클리어하는 모드. 카테고리를 모두 클리어하면 클리어 시간을, 못 채우면 클리어 개수를 기준으로 하는 전체 랭킹(TOP 10)에 이름이 오른다.
- 싱글모드 기록 보관: 플레이가 끝나면 결과를 예외 없이 DB에 남긴다. 기본 화면은 TOP 10을 보여주고, 옵션으로 전체 순위를 모두 펼쳐 볼 수 있다.
- 아이템 시스템: 라운드 승자 또는 아이템 미니 문제를 푼 참가자에게 랜덤 아이템 1개 지급. 공격형(3초 지연시키기, 초성 하나 가리기, 글자를 거꾸로 입력해야 인식되게 하기, 아이템 훔치기, 입력 지우기)과 방어형(공격 무효화)
- 난이도별 초성 마스킹 정도 조절(하/중/상)
- 사자성어·속담·동물·음식·도시·수도·과일·색깔·직업·스포츠 10개 카테고리

## Observable acceptance criteria

- 방장이 방을 만들면 공유 가능한 URL이 생성되고, 다른 사용자가 그 URL로 접속해 닉네임을 입력하면 대기실에 합류한다.
- 방장이 카테고리와 난이도를 선택하고 시작하면, 참가자 전원에게 동일한 초성 문제가 동시에 표시된다.
- 난이도에 따라 노출되는 초성 글자 수가 다르게 표시된다(예: "유구무언" 기준 하="유구ㅁ언", 중="유ㄱ무ㅇ", 상은 한 음절만 힌트로 남기고 나머지를 초성으로 가린다).
- 제한시간 내에 정답을 처음 제출한 참가자가 해당 라운드의 승자로 표시되고, 랜덤 아이템 하나가 지급된다.
- 참가자가 보유한 공격형 아이템을 특정 상대에게 사용하면, 대상에게 해당 방해 효과(지연/가림/역순 입력)가 적용된다.
- 방어형 아이템을 사용한 참가자는 공격형 아이템의 효과를 받지 않는다.
- 제한시간이 끝날 때까지 아무도 정답을 맞히지 못하면 승자 없이 다음 라운드로 넘어간다.
- 라운드 진행 중에는 화면 오른쪽에 참가자 이름과 현재 라운드 승수를 기준으로 한 순위가 실시간으로 갱신되어 표시된다.
- 10라운드가 모두 끝나면 라운드 승리 횟수를 기준으로 순위표가 표시되고, 동률인 참가자는 평균 정답 소요시간이 빠른 순으로 정렬된다.
- 싱글모드에서는 초성 문제가 무작위 속도로 위에서 아래로 떨어지며 계속 나타나고, 시간 안에 풀지 못해도 사라지지 않고 화면에 남아 기다린다.
- 싱글모드에서 선택한 카테고리의 문제를 모두 클리어하면, 제한시간이 남아 있어도 즉시 결과 화면으로 종료된다.
- 정답을 잘못 제출하면 오답임을 알 수 있게 표시하고 입력창을 비운다.
- 방 참여와 싱글모드 진입 모두 회원가입 절차 없이 가능하다. 닉네임 입력 시 랜덤 생성 버튼을 제공한다.
- 싱글모드 화면 오른쪽에는 전체 랭킹 TOP 10이 표시된다. 카테고리를 모두 클리어한 기록은 클리어 시간이 빠른 순으로, 그 아래로 다 채우지 못한 기록은 클리어한 개수가 많은 순으로 정렬된다.
- 멀티모드 대기실에는 참가자·설정과 별도로 채팅 영역이 있어 참가자끼리 실시간으로 메시지를 주고받을 수 있다. 방 공유 URL은 기본적으로 접혀 있고, 클릭하면 펼쳐진다.
- 라운드가 진행되는 동안 메인 문제 아래에 참가자별로 별도의 아이템 획득용 문제가 계속 제공된다. 이를 맞히면 즉시 랜덤 아이템을 얻고 새 문제로 바뀐다.
- 아이템 위에 마우스를 올리면 말풍선 형태로 설명이 표시된다.
- 게임에 처음 접속하면 닉네임 입력 화면이 먼저 나오고, 랜덤 생성 버튼으로 닉네임을 만들 수 있다. 닉네임을 확정한 뒤에야 싱글모드·멀티모드를 고를 수 있다.
- 닉네임을 한 번 만든 뒤 다시 접속하면 입력 화면을 건너뛰고 바로 모드 선택 화면이 나온다. 모드 선택 화면에서 닉네임을 다시 바꿀 수 있다.
- 방에 참여할 때 닉네임을 다시 입력하지 않고, 저장된 닉네임으로 곧바로 합류한다.
- 싱글모드 진행 중과 멀티모드 라운드 진행 중 화면에 게임 종료 버튼이 있고, 누르면 진행을 중단하고 홈(모드 선택) 화면으로 이동한다.
- 멀티방에서 게임 종료로 홈으로 이동한 참가자는 해당 방의 참가자 목록에서 사라지고, 다른 참가자 화면의 목록·순위에서도 즉시 빠진다.
- 라운드 진행 중 이탈로 남은 참가자가 1명이 되면 남은 라운드를 진행하지 않고 즉시 결과 화면으로 넘어가며, 그 1명이 승리자로 표시된다.
- 대기실에서 이탈해 남은 인원이 1명이 되면 게임이 시작된 적이 없으므로 종료 처리하지 않고, 그 1명은 대기실에 남아 다른 참가자를 계속 기다린다.
- 방장이 나가면 남아 있는 참가자 중 가장 먼저 들어온 사람이 새 방장이 되어 카테고리·난이도 설정과 시작 권한을 갖는다.
- 모든 참가자가 나간 방은 해체되어 목록에서 사라지고, 잠시 뒤 저장소에서도 지워진다. 해체 직후에 그 방 URL로 들어가면 해체되었다는 사유를 안내받는다.
- 멀티모드 방 목록의 각 방 항목에 참가 중인 참가자 닉네임 목록이 표시되고, 방장은 구분되어 표시된다.
- 게임이 진행 중인 방은 목록에서 참가자별 현재 순위와 라운드 승수가 함께 표시된다. 대기 중인 방은 순위 대신 참가자 목록만 표시된다.
- 멀티방 대기실에는 참가 중인 참가자 목록과 채팅 영역이 함께 표시되고, 참가자가 들어오거나 나가면 목록이 갱신된다.
- 싱글모드 플레이가 끝나면 결과가 순위 진입 여부와 무관하게 항상 DB에 저장된다. TOP 10에 못 드는 기록도 저장된다.
- 제한시간이 끝나 종료한 경우, 카테고리를 모두 클리어해 종료한 경우, 게임 종료 버튼으로 중도 이탈한 경우 모두 그 시점까지의 기록이 저장된다.
- 서버를 재시작한 뒤에도 이전에 저장된 싱글모드 기록이 랭킹에 그대로 남아 있다.
- 싱글모드 랭킹 영역에는 기본적으로 TOP 10만 표시되고, 전체 순위 보기 옵션을 누르면 저장된 모든 기록이 순위와 함께 표시된다.
- 전체 순위 목록의 각 기록에는 순위, 닉네임, 클리어 시간 또는 클리어 개수, 카테고리와 난이도, 기록 시각이 표시된다.
- 전체 순위에서 자신의 방금 기록이 몇 위인지 확인할 수 있다.
- 전체 순위는 한 번에 50개씩 표시되고, 더 볼 기록이 남아 있으면 더 보기로 이어서 볼 수 있다. 화면에는 저장된 전체 개수와 지금 표시된 개수가 함께 나온다.
- 페이지를 넘겨 이어 붙여도 순위 번호가 전체 기준으로 이어지고, 성적이 같은 기록은 같은 순위를 공유한다.
- 클리어 개수가 카테고리의 문제 수를 넘거나 정수가 아니면 기록을 저장하지 않고 거부한다.
- 전체 클리어 기록의 클리어 시간이 0 이하이거나 제한시간(60초)을 넘으면 저장하지 않고 거부한다.
- 전체 클리어로 제출한 기록의 클리어 개수가 카테고리 문제 수와 다르면 저장하지 않고 거부한다.
- 각 방은 서로 독립적으로 동작한다. 한 방의 진행·종료·해체가 다른 방의 카테고리·난이도·참가자·진행 상태에 영향을 주지 않는다.
- 방은 게임 한 판 동안만 존재한다. 게임이 끝나거나(10라운드 완주·1인 생존 종료) 방이 해체되면 그 방은 저장소에서 삭제되어 URL로 더 이상 들어갈 수 없다. 다만 그 판을 함께한 참가자는 결과 화면을 계속 볼 수 있다.
- 삭제된 방의 URL로 접근하면 오류가 아니라 방이 종료되었음을 알리고 돌아갈 수 있게 안내한다.

## Settled constraints and rationale

- 멀티모드는 2인 이상 4인 이하로 진행한다. (PRODUCT.md에서 확정)
- 참여는 URL과 닉네임만으로 가능하며 회원가입은 없다. 캐주얼한 사용성을 지키기 위함이다. (PRODUCT.md에서 확정)
- 순위는 라운드 승리 횟수를 기준으로 매기고, 동률이면 평균 정답 소요시간이 빠른 쪽을 우선한다. 기존 라운드 승부 규칙("1명이 맞히면 라운드 종료")과 자연스럽게 이어지고 구현·표시가 단순하기 때문이다. (이번 세션에서 확정)
- 문제·카테고리 데이터는 사전 제작된 DB를 기반으로 지속 업데이트한다. (PRODUCT.md에서 확정)
- 방은 게임 한 판의 수명만 갖는다. 종착 상태(`finished`/`disbanded`)에 도달하면 저장소에서 방을 지워, 끝난 방이 쌓이거나 재사용되지 않게 한다. (사용자가 확정)
- 방을 지우는 시점 판단은 페이즈를 읽어서 한다. 종료 조건(1인 생존, 무응답 해체, 10라운드 완주)은 `tick`과 `removePlayer`가 한 곳에서 판정하고, 삭제는 그 결과만 보고 실행한다. 조건이 늘어도 삭제 경로를 손대지 않게 하기 위함이다. (이번 세션에서 확정)
- 방이 삭제된 뒤에도 참가자 화면에는 결과가 남는다. 서버가 삭제 직전 상태를 응답으로 돌려주고, 클라이언트는 종착 상태를 확인하면 폴링을 멈춘다. 결과를 보여주려고 방을 살려두는 것보다 단순하다. (이번 세션에서 확정)
- 방은 게임 한 판의 수명만 갖는다. 게임이 끝나면 방을 삭제해, 끝난 방이 목록에 쌓이거나 재사용되지 않게 한다. (사용자가 확정)
- 게임 중 남은 인원이 2명 미만이 되면 방을 종료하고 삭제한다. 혼자서는 라운드 승부가 성립하지 않아 방을 유지할 의미가 없다. (사용자가 확정)
- 방장이 나가면 방을 지우지 않고 가장 먼저 입장한 남은 참가자에게 방장을 넘긴다. 로비에 남은 사람들이 방장 이탈만으로 방에서 밀려나지 않게 하기 위함이다. (이번 세션에서 확정)
- 게임 종료로 방이 삭제된 뒤에도 참가자 화면에는 최종 순위가 남는다. 서버가 삭제 직전 상태를 응답으로 돌려주고, 클라이언트는 종료를 확인하면 폴링을 멈춘다. 순위를 보여주려고 방을 살려두는 것보다 단순하다. (이번 세션에서 확정)
- 라운드 제한시간은 문제당 15초다. (이번 세션에서 확정)
- 상 난이도는 모든 음절을 가리지 않고 한 음절을 항상 힌트로 남긴다. 전부 가리면 난이도가 지나치게 가혹하기 때문이다. (사용자가 확정)
- 싱글모드는 선택한 카테고리의 문제를 모두 맞히면 제한시간과 무관하게 즉시 종료한다. (사용자가 확정)
- 싱글모드에서 떨어지는 문제는 시간 안에 못 풀어도 사라지지 않고 화면에 남아 기다린다. 너무 빨리 사라지면 안 된다는 사용자 피드백에 따른 것이다. (사용자가 확정)
- 싱글모드 랭킹은 카테고리·난이도를 구분하지 않는 전체 랭킹 하나로 운영한다. "전체 랭킹"을 요청한 사용자 의도를 그대로 반영했다. (사용자가 확정)
- 카테고리는 사자성어·속담·동물·음식·도시·수도·과일·색깔·직업·스포츠 10개로 운영한다. (사용자가 확정)
- 싱글모드 기록은 프로세스 메모리가 아니라 Supabase 테이블에 저장한다. 서버 재시작이나 다중 인스턴스에서도 기록이 사라지지 않아야 하기 때문이다. 방 상태(game_rooms)와 같은 방식이다. (사용자가 확정)
- 싱글모드 기록은 순위 진입 여부와 무관하게 모두 남긴다. "기록을 항상 남겨 달라"는 사용자 요청을 그대로 반영했다. (사용자가 확정)
- 랭킹 화면의 기본 노출은 TOP 10을 유지하고, 전체 순위는 사용자가 명시적으로 펼치는 옵션으로 둔다. 기본 화면이 길어지지 않게 하려는 것이다. (사용자가 확정)
- 전체 순위는 50개 단위로 페이지를 나눠 내려준다. 순위는 전체 기록을 기준으로 매겨 페이지를 넘겨도 번호가 이어진다. 기록이 쌓여도 응답이 무한정 커지지 않게 하려는 것이다. (이번 세션에서 확정)
- 기록 제출 값은 서버에서 카테고리 문제 수와 제한시간을 기준으로 검증한다. 클라이언트가 보낸 값을 그대로 믿으면 조작된 기록이 랭킹 상위를 차지하기 때문이다. (이번 세션에서 확정)
- 게임 종료 버튼으로 싱글모드를 중도 이탈해도 그 시점까지의 기록을 남긴다. "항상 남긴다"는 원칙을 중도 이탈에도 일관되게 적용한다. (이번 세션에서 확정)

## Assumptions

- 아이템은 라운드 진행 중(제한시간 카운트다운이 도는 동안) 아무 시점에나 사용할 수 있다고 가정한다. 상대를 방해하는 목적상 자연스러운 사용 방식이며, 되돌리기 쉬운 결정이다.
- 방어형 아이템은 보유만으로 자동 발동되지 않고, 참가자가 능동적으로 사용해야 효과가 적용된다고 가정한다. 다른 아이템과 조작 방식을 통일해 UI를 단순하게 유지하기 위함이다.
- 정답 판정은 공백을 제거한 완전 일치 방식으로 하고, 오탈자는 허용하지 않는다고 가정한다. 구현이 단순하고 초성게임 특성상 정확한 단어를 맞히는 것이 핵심이기 때문이다.
- 아이템은 획득 시 1개씩 누적되고 사용하면 소모되며, 보유 개수에 별도 제한은 두지 않는다고 가정한다. 최대 10라운드 안에서 자연스럽게 상한이 생긴다.
- 같은 종류의 아이템을 여러 개 보유하면 UI에는 하나로 묶여 개수(×N)로 표시하고, 사용하면 그중 하나가 소모되어 사라진다고 가정한다. (사용자가 확정)
- 아이템 획득용 미니 문제는 참가자마다 따로 주어지며(같은 문제를 여러 명이 다투지 않음), 라운드 승패나 순위에는 영향을 주지 않는 부가 보상으로 가정한다.
- "아이템 훔치기"·"입력 지우기"는 공격형 아이템으로 분류해 방어막으로 막을 수 있다고 가정한다. 기존 방해 아이템과의 일관성을 위해서다.
- 클리어 개수가 0인 기록도 저장한다고 가정한다. "항상 남긴다"는 요청을 예외 없이 적용하는 쪽이 규칙이 단순하다.
- 순위를 매기려면 전체 기록을 한 번 읽어야 하므로, 한 번에 읽는 양의 상한을 5000개로 둔다고 가정한다. 이 상한을 넘으면 오래된 기록이 집계에서 빠지고, 화면에 그 사실을 알린다.
- 싱글모드 기록은 익명 참가자가 남기므로 DB 접근은 서버 라우트 핸들러가 secret key로만 하고, RLS를 켜 클라이언트 직접 접근을 막는다고 가정한다. game_rooms 테이블과 같은 방침이다.

## Off-limits areas and why

- 계정/로그인 시스템: PRODUCT.md에서 회원가입 없이 캐주얼하게 참여하는 것으로 이미 확정했으므로 다루지 않는다.
- 지인이 아닌 상대와의 랜덤 매칭: 지인 기반 URL 공유 방식으로 확정했으므로 범위 밖이다.

## Deferred points

- 참가자가 나간 뒤 같은 방에 재접속하는 경우의 처리 방식(이탈 처리만 이번에 확정했다)
- 저장 기록이 순위 집계 상한(5000개)을 넘어설 정도로 늘어난 뒤의 보관 기간·정리 정책
- 구체적인 카테고리 목록(예: 사자성어, 속담 등)과 실제 문제 데이터
- 방장이 라운드 제한시간(15초)을 직접 조정할 수 있게 할지 여부

## Remaining risks

- 아이템 사용 타이밍에 대한 가정이 실제 기대와 다르면 라운드 진행 UI를 다시 설계해야 할 수 있다.
- 방어형 아이템의 발동 방식(능동 사용 vs 자동 발동)에 대한 가정이 틀리면 아이템 UI·로직을 재작업해야 할 수 있다.
- 재접속 처리가 정의되지 않아, 실수로 나간 참가자가 진행 중인 방으로 돌아올 방법이 없다.
- 기록을 항상 저장하므로 반복 플레이 시 행이 빠르게 늘어난다. 순위 집계 상한(5000개)을 넘어서면 오래된 기록이 순위에서 빠지고, 보관 기간 정책이 없어 테이블이 계속 커진다.
- 중도 이탈 기록까지 모두 남기면 클리어 개수가 낮은 기록이 다수 쌓여 전체 순위 목록의 가독성이 떨어질 수 있다.
- 싱글모드 전체 랭킹이 카테고리를 구분하지 않아, 단어 수가 적은 카테고리(예: 속담 6개)가 많은 카테고리(예: 사자성어 10개)보다 클리어 시간이 유리해 랭킹 공정성이 떨어질 수 있다.
- 대기실 채팅과 방 상태 조회가 같은 폴링 주기(0.7초)를 공유해 채팅이 즉시성이 낮게 느껴질 수 있다.
- 이탈 판정은 참가자가 보내는 나가기 신호(버튼·페이지 종료)에만 의존한다. 브라우저가 강제 종료되거나 네트워크가 끊기면 신호가 오지 않아, 그 참가자가 방에 남은 것으로 보인다. 2인 방에서 이렇게 되면 남은 1명이 끝나지 않는 라운드를 기다릴 수 있다.
