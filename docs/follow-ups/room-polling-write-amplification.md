# 폴링마다 방 쓰기를 시도해 DB 쓰기가 증폭됨

`lib/game/room-store.ts`의 `getRoom`은 `tick`이 상태를 바꿨을 때만 저장하지만, 라운드 경계에서는 4명의 폴링 요청이 같은 version을 읽고 모두 저장을 시도한다. 낙관적 락 덕에 하나만 성공하고 나머지는 재시도 후 올바른 상태를 읽으므로 정확성 문제는 없다. 다만 라운드가 넘어가는 순간마다 불필요한 쓰기·재읽기가 발생한다.

라운드 진행을 폴링이 아니라 별도 경로(예: 서버 측 스케줄러나 Supabase Realtime + DB 함수)로 옮기면 해소된다.
