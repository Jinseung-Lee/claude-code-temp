# 신호 없이 끊긴 참가자를 이탈로 판정하지 못함

이탈 처리는 참가자가 보내는 신호에 의존한다. 화면의 "게임 종료" 버튼
(`DELETE /api/rooms/[code]`)과 탭을 닫을 때의 `sendBeacon`
(`POST /api/rooms/[code]/leave`)이 그 신호다.

브라우저가 강제 종료되거나 기기가 절전에 들어가거나 네트워크가 끊기면 신호가
오지 않는다. 그러면 이미 사라진 참가자가 `players`에 남아, 2인 방에서는 남은
1명이 끝나지 않는 라운드를 기다리게 된다.

게임이 시작된 방은 20초 무응답 해체(`LOBBY_IDLE_TIMEOUT_MS`) 대상이 아니라
이 경우를 걸러주지 못한다. 폴링 요청마다 참가자별 `lastSeenAt`을 기록하고,
`tick`에서 일정 시간 갱신이 없는 참가자를 `removePlayer`와 같은 경로로
정리하면 해결된다. 폴링이 이미 0.7초마다 돌고 있어 별도 하트비트는 필요 없다.

강의용 규모에서는 사용자가 대개 버튼이나 탭 닫기로 나가므로 주 경로는 동작한다.
